Lo que trabajamos hoy — en orden
1. Conexión a IBM i con ODBC
Se exploró ODBC como método de conexión. Se identificó que el driver IBM i Access ODBC no estaba instalado y que no había permisos de admin para instalarlo en la laptop de trabajo.
Conexión
2. Pivote a SSH con phpseclib
Se propuso conectar Laravel al IBM i via SSH usando phpseclib, sin necesidad de instalar drivers. Se confirmó que la conexión SSH funciona correctamente a 192.168.250.22 con el usuario robertomv.
Conexión
3. Diagnóstico de permisos en el LPAR
Se identificó que db2 estaba bloqueado por permisos. Se descubrió que qsh -c "db2 '...'" funciona correctamente. Se otorgaron permisos sobre la librería R1 con GRTOBJAUT. Se confirmaron datos reales de la tabla R1.T1 con usuarios IBM i.
IBM i
4. Pivote final a Bridge Java con JTOpen
Se descartó el .jar por restricciones de descarga pero el usuario lo resolvió por su cuenta. El Bridge Java quedó corriendo en la laptop de trabajo en http://192.168.1.13:8080 con datos reales del IBM i. Se verificó el endpoint /api/health.
Conexión
5. Creación del proyecto Laravel
Se creó el proyecto Laravel en C:\xampp\htdocs\CatrachoMayaTech-Laravel. Se instaló Guzzle y se levantó con php artisan serve.
Código
6. Backend del Comparador de Objetos
Se generó el código completo: IBMiBridgeService.php, ComparadorController.php con lógica de comparación DEV/QA/PROD y generación de paquete de pase, SystemHealthController.php y rutas en api.php.
